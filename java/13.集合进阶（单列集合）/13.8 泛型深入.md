###  一、概念
   泛型：是`JDK5`中引入的特性，可以在编译阶段约束操作的数据类型，并进行检查
   泛型的格式：<数据类型>
   注意：泛型只能支持引用数据类型

### 二、泛型的好处
  1. 统一数据类型
  2. 把运行时期的问题提前到了编译时期，避免了强制类型转换可能出现的异常

### 三、扩展：`Java`中的泛型是伪泛型
  通俗一点理解就是只在编译的时候确定传入数据是否正确，存进集合中又会将该类型变成`Object`类型，当把数据提取出来之后，又会把数据转变成原来的类型
  在代码中的体现，泛型在Java文件中是真是存在的，但在`class`文件中泛型就会消失，这个过程叫做泛型的擦除

### 四、泛型的细节
  1. 泛型中不能写基本数据类型
  2. 指定泛型的具体类型之后，传递数据时，可以传入该类类型或其子类类型
  3. 如果没有写泛型，类型默认是`Object`

### 五、泛型的多处定义
  类后面              泛型类
  方法上面           泛型方法
  接口后面           泛型接口

  1. 泛型类
    使用场景：当一个类中，某个变量的数据类型不确定时，就可以定义带有泛型的类
    格式：`修饰符 class 类名<类型>{}`
    例：`public class ArrayList<E>{}`
  2. 泛型方法
    方法中形参类型不确定时，可使用类名后面定义的泛型，这样所有方法都可使用。还可在方法申明上定义自己的泛型，这只有本方法能用
    格式：`修饰符<类型> 返回值类型 方法名(类型 变量名){}`
    例：`public <T> void show(T t){}`
  3. 泛型接口
    两种使用方法：
       实现类给出具体的类型
       实现类延续泛型，创建实现类对象时再确定类型
    格式：`修饰符 interface 接口名<类名>{}`
    例：`public interface List<E>{}`

### 六、泛型的继承和通配符
  1. 泛型不具备继承性，但是数据具备继承性
  2. 使泛型呈现继承性，可以使用泛型方法。这样就可以接收任意类型的数据，但这也恰恰是弊端
  3. 为避免接收任意类型数据，而是接受特定类型数据，可以使用 `?` 通配符
    `? extends E`：表示可以传递E或者E所有的子类类型
    `? super E`：表示可以传递E或者E所有的父类类型
    
    应用场景：
       在定义类、方法、接口的时候，若类型不确定，就可以定义泛型类、泛型方法、泛型接口
       若类型不确定，但是能知道以后只能传递某个继承体系时，就可以使用泛型的通配符
